# B题技能分工与调用约束

本文件与 `.agents/project_config.json` 构成本项目的技能配置。题面以项目根目录和 `problem_files/` 中的新版 PDF 为准；Excel 附件不重写。当前交付范围为问题一，四问正式论文流水线尚未完成。

| 技能 | 本题职责 | 本次调用条件/交付 |
|---|---|---|
| paper-workflow-orchestrator | 统一阶段判断、输入预检和断点记录 | 已完成PDF与附件的S0预检；Q1单独交付不冒充S8正式论文 |
| problem-doc-model-selector | 抽取四问、数据需求与约束 | 已解析新版PDF；用 `.agents/configure_q1_route.py` 将Q1误判的“预测/回归”纠正为机理仿真，并同步A–D文件 |
| modeling-paper-rubric-and-model-selector | 模型路线及评分证据映射 | 已重建 `paper_output/plan/model_route.json`，Q1为五层多相模型及跨温度验证 |
| authoritative-data-harvester | 补充缺失参数的权威来源 | 附件足以支撑Q1主要参数时不抓取；Q2–Q4若需外部参数，先记录来源与适用条件 |
| data-cleaning-and-visualization | 数据清单、字段口径与图表计划 | 附件2专用读取位于 `问题1/data.py`；保持零下温度与电流密度原值，不自动做通用归一化 |
| sympy | 方程、量纲、符号及必要的解析核对 | Q1使用附件公式和有限体积离散；符号计算只作核对，不替代实验校准 |
| pymoo | 后续多目标/约束优化 | Q1不启用；问题二至四确定目标与约束后再启用。当前数值环境未安装pymoo |
| model-code-and-result-generator | 正式论文的结构化结果证据契约 | Q1先使用 `问题1/model.py`、`run.py` 与 `results/metrics.json` 输出真实证据；全四问完成后再汇总到正式S4契约 |
| quality-assurance-auditor | 正式稿证据门禁与反空洞审计 | Q1先用 `问题1/checks.py` 检查数据、题表、守恒、物理边界与收敛；四问证据齐全再运行正式门禁 |
| context-memory-keeper | 当前阶段、数据冲突及限制记录 | 已更新项目本地 `memoryskill.md` 与 `paper_output/context/workflow_memory.*` |
| paper-formal-writer | 完整论文的自适应正文与Word成稿 | 仅四问证据门禁通过后启用；问题一独立报告在 `问题1/问题1解决报告.md` |
| paper-micro-unit-generator | 正式论文局部修复或明确要求的快速骨架 | 当前不启用，避免把占位文字写入问题一报告 |

执行顺序是：PDF/附件预检 → 四问解析 → Q1机理路线校正 → 数据口径检查 → Q1求解和跨工况验证 → Q1专用检查 → Q1报告。后续用户要求解决问题二至四时，沿现有模型路线扩展电堆和控制问题，再运行完整证据门禁与论文输出。`问题1/results/run_manifest.json` 保存本次Q1代码、输入与结果的散列；若修改模型或数据，必须重新运行 `问题1/run.py` 并通过 `问题1/checks.py`。
